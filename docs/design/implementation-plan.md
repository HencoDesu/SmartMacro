# План реализации макета SmartMacro UI

Источник: `docs/design/smartmacro-ui.dc.html` (проект Claude Design `6f49190f`), разложен по вариантам в `opt-1*.html`. Токены визуального языка — `nocturne-tokens.md`.

## Что выбрано

| Вариант | Что это | Статус |
|---|---|---|
| **1b** | Главное окно: одно окно, слева режимы (Окна / Макросы / Прогоны / Шаблоны / Лог) + сводка по тегам, справа рабочая область, полоса прогонов всегда внизу | **выбрано автором макета** |
| **1d** | Редактор — canvas с живым прогоном: библиотека слева, граф в центре, лог прогона снизу, инспектор справа | основной режим правки |
| **1e** | Правка ноды на месте (двойной клик разворачивает бокс в редактор самого себя) | второй способ, вместе с 1d |
| **1f** | Ловушка хоткея: пусто → ловит → захвачено (кейкапы) → **конфликт** | виджет |
| **1g** | Бейдж фильтра целей: «8 окон · кроме Склад», разворот показывает поимённо | виджет |
| 1a | Главное окно отдельным окном (как сейчас) | не выбран |

Ключевое следствие 1b: **редактор перестаёт быть модальным диалогом**. Сейчас это `MacrosDialog`; станет режимом в одном окне.

## Волны

Выполнять строго после стадии 3 (App должен уже говорить по IPC — иначе всё это пишется дважды).

### D1. Токены Nocturne в Avalonia — ✅ `badcadd`
`ResourceDictionary` с рампами, отступами, радиусами, тенями + `ControlTheme` для Button / TextBox / ComboBox / CheckBox по правилам системы (обводка вместо заливки, состояния из рампы, фокус — 2px акцент). Inter в ресурсы приложения. Проверка: существующие экраны перекрашиваются без правки разметки.

Три дефекта нашлись только глазами, сборка и тесты их пропускали: классы `.accent`/`.danger` стояли после `:disabled` и при равной специфичности побеждали порядком — отключённые кнопки рисовались активными; кольцо фокуса не рисовалось вообще, потому что `AdornerLayer.IsClipEnabled` по умолчанию `true` и срезает ровно тот отступ 2px, которым кольцо живёт; `▶` U+25B6 приезжал белым эмодзи мимо `Foreground` (emoji-презентация тянет Segoe UI Emoji вопреки заданному шрифту) — заменён на U+25B8.

Ссылки между словарями — только `{DynamicResource}`: `{StaticResource}` через границу словаря здесь ненадёжен.

### D2. Оболочка 1b — ✅ `34d6dac`
Одно окно: сайдбар режимов со счётчиками, сводка тегов внизу сайдбара, полоса прогонов внизу всегда. Режим «Окна» — плотные строки 32px в колонках `160 / 88 / 1fr`, неопознанные отдельной группой внизу с приглушением и активным полем тега. `MacrosDialog` растворяется в режиме «Макросы». Трей-иконка и hide-to-tray уже удалены стадией 3.

Своя полоса заголовка 30px через `ExtendClientAreaToDecorationsHint` — системная всё равно рисуется светлой вопреки `RequestedThemeVariant`. Виды не подменяются в `ContentControl`, а переключаются видимостью: недописанный тег и грязное состояние редактора переживают смену режима.

Приостановка хоткеев привязана к режиму «Макросы», а не к «взведён пикер»: взвод происходит по клику, а suspend — round trip, первое нажатие успело бы проскочить. При закрытии окна resume дожидается ответа — **демон не перерегистрирует хоткеи сам при обрыве клиента.**

«Шаблоны» и «Лог» отрисованы с честной пустотой и пустым счётчиком — данных за ними нет. `templates/` по IPC не перечисляется и не читается; журнал демона через трубу не ходит вовсе. Обоим нужны новые типы сообщений, и журналу — то же событийное русло, что и D5.

### D3. Canvas (1d + 1e) — разбита надвое
Боксы нод «строками с переносом», рёбра в жёлобах между рядами, у условной ноды оба исхода — подписанные строки внизу бокса (важно: «в конец» не создаёт лишний узел). Пан/зум, перетаскивание, перекоммутация. Инспектор справа (1d) и разворот бокса на месте (1e) — оба, одиночный клик наполняет инспектор, двойной разворачивает. Выпил rows-редактора.

- **D3a** — ✅ `e8897ae`. Canvas целиком, только `SmartMacro.App`. Строковый редактор удалён.
- **D3b** — ✅ `f28f5b7`. Событийное русло прогона: нода, исход, деталь, длительность по IPC.

Группировка библиотеки (решение на запись): префикс — текст до первого дефиса, группой становится префикс, общий **двум и более** макросам, остальное — «прочее». Правило «всё без дефиса — в прочее» отвергнуто: в самом макете «Баг госта · 5» содержит и `Баг госта-Лучник`, и просто `Баг госта`.

Единица прогона — **обход**, не прогон: `RunMacroNode` с селектором форкает по обходу на окно, и все они делят один `RunId`. Чип в макете с `0x140804` — дескриптор окна, а не номер прогона. Отсюда переключатель обходов в полосе лога: иначе веер на десять окон зажёг бы десять боксов одного графа.

Три меры против затопления — по подписке, склейка в пачки не чаще 50 мс, ограниченная очередь со счётом потерь — описаны в `CLAUDE.md`. Коротко: очередь соединения в 256 отключает неуспевающего клиента, а веер даёт сотни событий за сотни миллисекунд, так что без склейки панель отваливалась бы ровно в тот момент, ради которого всё это и делается.

Окно выросло 900×482 → 1520×840: на 900 рельс, библиотека и инспектор оставляли графу меньше 200px.

### D4. Виджеты 1f и 1g
Ловушка хоткея с кейкапами и состоянием конфликта; бейдж целей с живым числом окон и разворотом. Требуют IPC-запросов из таблицы выше.

### D5. Отладчик
Пауза/шаг/до курсора/брейкпоинты в исполнителе, поток событий прогона по IPC, подсветка на canvas, синхронный лог, панель переменных со статическим анализом.

## Порядок и риск

D1 → D2 → D3 — визуальная часть, каждая волна самодостаточна и заметна. D4 и D5 добавляют движку функции; D5 самая крупная и трогает `MacroExecutor`, который сейчас покрыт 86 тестами — их придётся расширять, а не переписывать.

Отладчик утверждён автором, так что оговорка «остановиться после D3 и посмотреть, нужен ли он в заявленном объёме» снята. Но её половина сохраняется по существу: подсветка текущей ноды и лог отделены от паузы и брейкпоинтов и уезжают вперёд, в D3b. Если пауза/шаг окажутся невостребованными, потеряна будет только D5, а не то, чем пользуются каждый день.

Волны идут строго по одной. Не из осторожности: две параллельные `dotnet build` дерутся за `obj/`, а посторонняя сборка портит замеры памяти.
