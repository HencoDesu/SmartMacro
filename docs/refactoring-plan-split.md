# План рефакторинга SmartMacro: node-граф макросов (теги + триггеры) + разделение Daemon/UI

> Статус: ПЛАН, не применён  
> Способ применения: одна сессия, этапы → волны → сабагенты, build-гейт после каждой волны

Проект отвязывается от Perfect World, переименовывается в **SmartMacro** и становится универсальным инструментом оконной автоматизации: макрос = **граф нод** (действия, условия, ветвления, циклы) с триггерами активации (хоткей / появление процесса); окна несут **теги**; ввод маршрутизируется **тег-селекторами**. Затем — разделение на фоновый `Daemon` (~40–60MB) и Avalonia `App` по требованию.

Порядок: переименование → generic-движок на нодах (этап 0) → разделение процессов (этапы 1–4).

## Принятые решения

| Вопрос | Решение |
|---|---|
| Имя проекта | **SmartMacro** (`SmartMacro.Native/Contracts/Core/Daemon/App`). Переименование — первой волной W0.0 |
| Представление макроса | **Граф нод**: нода действия → ссылка `Next`; условная нода (Find/Wait/Recognize) → ссылки по исходам (`Found`/`NotFound`/`Timeout`). Цикл = ребро назад, легален. null-ссылка = конец. Единый формат: линейный макрос = вырожденная цепочка |
| Скриптовый язык | **Не в v1.** Собственный DSL не пишем никогда. Lua (Lua-CSharp, fallback Jint) — бэклог как escape-hatch, когда понадобятся переменные/выражения. Expression-ноды в граф НЕ растим (анти-цель: Blueprint-спагетти) — вместо них тогда придёт ScriptNode |
| Условные ноды и мульти-окна | Find/Wait/Recognize работают **только по контекст-окну**. Независимое ветвление на N окнах = `RunMacroNode` с селектором (под-запуск на каждом окне со своим контекстом) |
| `RunMacroNode` | По умолчанию ждёт завершения всех под-запусков, потом `Next`; флаг `Await=false` для fire-and-forget. Глубина ≤ 4 + детект цикла имён |
| Переменные | Run-scoped словарь. **Пишут только триггер** (`cursor` — точка курсора на момент срабатывания, всегда) **и результаты условных нод** (`RecognizeTagNode` → имя тега; `Find/Wait` → точка находки). Читатели: `ClickNode` (точка из переменной), строковые параметры через подстановку `{имя}`. Произвольный `SetVariableNode`/арифметика/сравнения — **НЕ в v1** (сигнал к ScriptNode). Отдельная `ClickAtCursorNode` не нужна — это `ClickNode` с `PointVar: "cursor"` |
| Elevation обоих процессов | Оба elevated. ⚠️ **QUESTIONABLE** — вернуться и убрать повышение прав где не нужно |
| Exit демона при открытом UI | Диалог «демон остановлен» → выход UI |
| Автозапуск с Windows | Отложен |
| Хранение | Папка `macros/`, `{Имя}.json` = один граф |
| Триггер по добавлению/снятию тега | Не в v1 — цепочки через явный `RunMacroNode` |
| Runaway-циклы | Без жёсткого таймаута (вечный watchdog легитимен). Реестр запущенных макросов + cancellation + Stop из UI + single-flight по имени. Статический warning: цикл без Delay/Wait-ноды внутри |
| Canvas-редактор | Отдельная волна, НЕ блокирует остальное: rows-редактор правит параметры нод любого графа и структуру цепочек; canvas нужен только для перекоммутации ветвистых графов |
| Тесты | Возвращаются с W0.0. **TUnit** (Microsoft.Testing.Platform, source-gen, async-first) + **FakeItEasy** для дублей + ассерты TUnit'а встроенные (`await Assert.That(...)`; FluentAssertions не берём — коммерческая лицензия v8+). Логгеры — `NullLogger<T>`, не мокаются. Швы под подмену обязаны быть интерфейсами (FakeItEasy = interface/virtual only): слой примитивов, реестр окон, `IIpcClient`. Тесты пишутся **в волне, которая пишет код** (definition-of-done), гейты = build+test. Юнитами НЕ покрываем: живой Win32-ввод, реальную игру, Avalonia-рендер, трей — ручная приёмка |

## Этап 0 — Generic-движок: окна, теги, ноды

### 0.0 Переименование в SmartMacro (W0.0)

Solution, проекты, namespaces, папки: `PerfectWorldAgent.*` → `SmartMacro.*`. Обновить slnx, csproj, `app.manifest`, using'и, `CLAUDE.md`, имена mutex/pipe (`smartmacro-daemon`, `smartmacro-control`). Первой волной — весь новый код пишется в правильных namespace. Build-гейт.

### 0.1 Домен: окна и теги вместо агентов и классов

- **`ManagedWindow`** (замена `CharacterAgent`): hwnd + процесс + **множество тегов** (строки). Стейтмашины нет — Stateless выпиливается; «идентифицирован» = «есть теги». Окно умерло → запись удаляется. Реестр окон (`WindowRegistry`) — единственный владелец тегов, операции атомарны, события `WindowAppeared/TagsChanged/WindowClosed`.
- Теги — runtime-состояние, не персистятся (hwnd эфемерны). Вешаются нодами макросов и вручную из UI.
- **`CharacterClass` enum, `MasterClass`, `IgnoredClasses` удаляются** — их заменяют теги и селекторы. Шаблоны `Assets/GameClassNames/*.png` → набор шаблонов, имя файла = тег.
- **Профили процессов** (`ProcessProfiles` в appsettings): `{ ProcessName, ActivationLParam?, SettleDelayMs, DeactivationDelayMs, InterStepDelayMs }`. Заменяют `Agent:GameProcessName` + `Input:Activating` — wake-up-танец с `WM_ACTIVATEAPP` это особенность PW. Профиль без ActivationLParam = обычный ввод. ProcessMonitor следит за объединением имён профилей.

### 0.2 Модель макроса: граф нод

```
Macro {
    Name,                          // = имя файла (валидация NTFS)
    Triggers: [ HotkeyTrigger(modifiers, key|mouseButton)
              | ProcessAppearedTrigger(processName) ],   // контекст = новое окно
    StartNodeId,
    Nodes: [ MacroNode ]
}

MacroNode (JSON-полиморфизм $type; общее: Id, Editor {X,Y}? — координаты canvas):
  // действия (одно ребро Next; Target? = селектор {RequireTags[], ExcludeTags[]},
  // null = контекст-окно; fan-out по совпавшим окнам параллельно):
  KeyPressNode      { Key, Target?, Next }
  ClickNode         { Point | PointVar, Dbl, Target?, Next }   // ровно одно из двух: литерал или переменная ("cursor")
  DelayNode         { Ms, Next }                                // глобальная пауза сценария
  AddTagNode        { Tag, Target?, Next }                      // Tag поддерживает {var}-подстановку
  RemoveTagNode     { Tag, Target?, Next }
  SetIconNode       { IconPath, Target?, Next }                 // путь поддерживает {var}: "icons/{tag}.png"
  RunMacroNode      { MacroName, Target?, Await=true, Next }

  // условные (контекст-окно; рёбра по исходам; результаты пишутся в переменные):
  FindElementNode      { Template, Region?, FoundPointVar?, Found, NotFound }
  WaitForElementNode   { Template, Region?, TimeoutMs, FoundPointVar?, Found, Timeout }
                       // FoundPointVar: центр найденного шаблона → переменная-точка.
                       // Паттерн "найти кнопку где угодно и кликнуть" = Find(весь экран,
                       // FoundPointVar: "btn") →Found→ Click(PointVar: "btn") — частично
                       // снимает и проблему привязки к разрешению
  RecognizeTagNode     { TemplateSet, Region, ApplyTag=true, ResultVar="tag", Matched, NotMatched }
                       // лучший матч набора выше порога; ApplyTag → тег = имя шаблона;
                       // имя также пишется в переменную ResultVar
```

**Переменные** — словарь на один запуск макроса (имя → строка | число | точка):
- Инициализация триггером: `cursor` (точка курсора на момент срабатывания) — пишется всегда, для любого способа запуска (хоткей, process-appeared, UI-Run).
- Пишут только триггер и условные ноды (`ResultVar`/`FoundPointVar`). `SetVariableNode` и выражения — не в v1.
- Чтение: `PointVar` у ClickNode; `{имя}`-подстановка в строковых параметрах (Tag, IconPath, MacroName). Отсутствующая переменная на чтении = ошибка ноды → макрос прерывается с логом (явный отказ лучше тихого промаха).
- Под-запуски `RunMacroNode` получают **копию** переменных родителя (чтение наследуется, обратной записи нет — параллельные под-запуски не гоняются за общим состоянием).

- **Контекст-окно**: у запуска от `ProcessAppearedTrigger` и у под-запусков `RunMacroNode` с селектором. Хоткей-запуск контекста не имеет → валидация при сохранении: условные ноды и безселекторные действия требуют контекста.
- Все регионы/точки — внутри нод, редактируются пользователем. Из appsettings уходят все зашитые координаты/регионы/шаблоны/бинды.
- **`hotkeys.json` удаляется**: хоткей = триггер в файле макроса. `HotkeyListener` перерегистрируется при изменениях библиотеки.
- Шаблоны: `templates/{имя}.png` (Find/Wait) и `templates/{набор}/{тег}.png` (Recognize). Текущие `Assets/GameUiElements` и `GameClassNames` переезжают.

### 0.3 Исполнение

- **`MacroExecutor`**: walker — исполнить ноду → перейти по ребру (у условных — по исходу); null-ребро = конец. Fan-out действий по селектору — `Task.WhenAll`. `RunMacroNode` с селектором — параллельные под-запуски с контекстом, await по флагу.
- **Слой примитивов** (нажать/кликнуть/найти/распознать/тег/иконка) отделён от walker'а — будущий ScriptNode/Lua биндится к нему же.
- **Реестр запущенных макросов**: runId, имя, время старта, CTS, текущая нода (для будущей визуальной отладки). Stop из UI; отмена всех на shutdown; повторный триггер бегущего имени — no-op с логом.
- Пер-окно single-flight (`_operationLock` в `ManagedWindow`) гейтит контекстные запуски (boot на окне); одиночные fan-out-действия не гейтятся (эквивалент сегодняшней иммунки поверх макроса).
- Статические проверки при сохранении/загрузке: недостижимые ноды (warning), битые ссылки (error), цикл без Delay/Wait внутри (warning), условная нода без контекста (error).
- Старые сообщения (`UseImmunityMessage`, `TakeAssistMessage`, `EnterIdentifyMessage`, `ClickAtMessage`, `RunMacroMessage`) и `OrchestratorTrigger` удаляются — одна цепочка «триггер → MacroExecutor».
- `AgentInputDispatcher` остаётся (activate→send→deactivate), настройки — из профиля процесса окна.

### 0.4 Хранение и дефолты

- `macros/` папка, watcher, CRUD по файлу, валидация NTFS-имён. Одноразовая миграция `macros.json`: линейные списки → цепочки нод; per-class блоки → `RunMacroNode` с селекторами по тегам-классам.
- **Дефолтные PW-примеры** (первый запуск, папка пуста): `pw-boot` (`ProcessAppearedTrigger`: Wait server-select →Found→ Click →…→ Wait in-world →Found→ KeyPress C → Recognize(ResultVar:"tag") →Matched→ SetIcon("icons/{tag}.png") → KeyPress C; ветка Timeout → конец), `pw-immunity`, `pw-assist` (клик слот-1 + клавиша, ExcludeTags:[МАСТЕР]), `pw-cursor-click` (ClickNode с PointVar:"cursor"). «Встроенное» поведение = редактируемые файлы примеров, `pw-boot` — витрина ветвления и переменных.

### 0.5 UI

- **Главное окно**: окна отслеживаемых процессов с чипами тегов (добавить/снять вручную), процесс, hwnd; секция «Запущенные макросы» со Stop.
- **Rows-редактор** (эволюция текущего): триггеры (пикер хоткея / имя процесса) + список нод. Для **цепочек** — полное редактирование (добавить/удалить/переставить = перешить Next автоматически). Для **ветвистых графов** — параметрический режим: правка полей нод (координаты, клавиши, тайминги, селекторы) без перекоммутации рёбер + плашка «структура — в визуальном редакторе». Детект цепочки: у всех нод одиночный Next, нет двойных входов, нет циклов.
- **Canvas-редактор** — отдельная волна: спайк NodifyM.Avalonia vs самописный Canvas (боксы + рёбра + пан/зум — нам не нужны мульти-пины). Не блокирует: параметры любого графа правятся в rows-режиме.
- **Settings**: только профили процессов (v1 — правка в appsettings, диалог в бэклог).

### 0.6 Тесты

Проект `SmartMacro.Tests` создаётся в W0.0; каждая волна сдаёт свой код вместе с тестами; гейт волны = `dotnet build` + прогон тестов зелёные.

**Стек:**
- **TUnit** — раннер и ассерты (`await Assert.That(x).IsEqualTo(y)`). Работает на Microsoft.Testing.Platform: гейт-команда — `dotnet run --project tests/SmartMacro.Tests` (надёжный путь) и/или `dotnet test` с включённым MTP-режимом SDK .NET 10; какой из них закрепить — решает tooling-спайк в W0.0. Параллелизм по умолчанию — тесты пишутся изолированными; для vision-фикстур и temp-каталогов при необходимости `[NotInParallel]`.
- **FakeItEasy** — дубли (`A.Fake<T>()`, `A.CallTo(...).Returns(...)` / `.MustHaveHappened()`). Только interface/virtual ⇒ архитектурное требование: слой примитивов, реестр окон, `IIpcClient` — интерфейсы. Логгеры — `NullLogger<T>` (без моков). Простые записывающие fakes руками там, где надо ассертить последовательность вызовов walker'а — часто проще fake'а.
- FluentAssertions **не берём** (v8+ коммерческая); ассертов TUnit достаточно.
- Fallback: если TUnit/MTP конфликтует с тулингом окружения (IDE, агентские прогоны) — откат на xUnit в W0.0 стоит ~ничего; после W0.1 откат дорожает, поэтому спайк обязателен первой задачей.

| Область | Что покрываем | Как |
|---|---|---|
| Walker графа | обход, выбор рёбер по исходам, null-ребро = конец, циклы, глубина/детект цикла `RunMacroNode`, Await-семантика, cancellation | fake-слой примитивов (запись вызовов), fake-реестр окон |
| Переменные | init триггером (`cursor`), `ResultVar`/`FoundPointVar`, `{var}`-подстановка, ошибка на отсутствующей, копия в под-запуск | там же |
| Селекторы | Require/Exclude против реестра, снепшот-семантика, fan-out по N окнам | fake-реестр |
| Статическая валидация | битые ссылки, недостижимые ноды, hot-loop warning, «условная нода без контекста» | чистые юниты |
| Сериализация | JSON round-trip всех типов нод/триггеров (полиморфизм `$type`), обратная совместимость при добавлении полей | чистые юниты |
| Миграция | старый `macros.json` → графы (линейные + per-class) | фикстуры старого формата |
| `WindowRegistry` | атомарность тегов, события, снятие при смерти окна | чистые юниты |
| Vision golden-фикстуры | матчер против эталонных PNG из `samples/`: скоры выше/ниже порога, региональный кроп, grayscale-путь | фикстуры-скриншоты в репо (перенос из `samples/`) |
| Сторы/watcher | load/persist/skip-unknown, debounce-hot-reload (минимально — flaky-зона) | temp-каталоги |
| IPC (этапы 2–3) | конверт: корреляция Id, события, мультиклиент; reconnect-логика клиента | in-memory duplex stream вместо pipe |
| VM (этапы 3+) | список окон/тегов, редакторы против fake `IIpcClient` | fakes |

Вне юнит-покрытия (только ручная приёмка): живой ввод в игру, PrintWindow с реальных окон, трей, Avalonia-рендер, RegisterHotKey.

## Этап 1 — Contracts

`SmartMacro.Contracts` (→ Native): модель графа целиком (ноды/триггеры/селекторы), `WindowDto { Hwnd, ProcessName, Title, Tags[] }`, `RunningMacroDto`, IPC-конверт. **App теряет ссылку на Core** (OpenCV/Tesseract не едут в UI): App → Contracts+Native; Core → Contracts+Native; Daemon → Core+Contracts+Native.

## Этап 2 — Daemon (2 агента параллельно)

- **A: хостинг + трей.** `SmartMacro.Daemon` (WinExe, `requireAdministrator` ⚠️ QUESTIONABLE, single-instance mutex), перенос DI/Serilog/appsettings из App, `Native/Tray/Win32TrayIcon` (Shell_NotifyIcon + message-окно + TrackPopupMenu, по образцу `Win32HotkeyMonitor`), меню «Открыть панель»/«Выход».
- **B: IPC-сервер.** Pipe `smartmacro-control`, JSON Lines, многоклиентность, диспетчер, push-события. **+ протокольные тесты на in-memory duplex stream** (корреляция, события, мультиклиент).

### Каталог IPC

| Запрос | Payload | |
|---|---|---|
| `GetWindows` | — | снепшот окон с тегами |
| `AddTag` / `RemoveTag` | hwnd, tag | ручное управление из UI |
| `RunMacro` | name | Run из редактора (курсор-контекст резолвит демон) |
| `GetMacros` / `SaveMacro` / `DeleteMacro` | — / граф / name | CRUD по файлам |
| `GetRunningMacros` / `StopMacro` | — / runId | реестр запусков |
| `SuspendHotkeys` / `ResumeHotkeys` | — | **критично** для пикера хоткеев в редакторе (RegisterHotKey в демоне) |
| `GetProcessProfiles` / `ReplaceProcessProfiles` | профили | если делаем UI-редактирование |
| `DumpCaptures` | — | отладка vision |
| `Shutdown` | — | опционально |

События: `WindowAppeared` / `WindowTagsChanged` / `WindowClosed`, `MacrosChanged`, `RunningMacrosChanged`, `ActivateWindow`.

## Этап 3 — App-слим (1 агент)

Без ссылки на Core; `IpcClient` (reconnect, `Disconnected` → диалог + выход); VM на IPC; удалить `TrayIconHost` и hide-to-tray (закрытие = выход); автозапуск демона при отсутствии; активация окна по `ActivateWindow`; минимальный собственный `appsettings.json` (Serilog UI). **+ тесты reconnect-логики клиента (fake stream) и VM против fake `IIpcClient`.**

## Этап 4 — полировка (2 агента параллельно)

- **A: память.** GC-тюнинг демона (`ServerGarbageCollection=false`, `ConcurrentGarbageCollection=false`, `GCConserveMemory`), lazy-OpenCV, замеры (цель: демон ≤ 60MB idle).
- **B: документация + чистка.** `spec.md` переписать под SmartMacro (PW — пресет примеров, раздел про тесты и команду `dotnet test`), `CLAUDE.md`, dead-code sweep, финальный build+test-гейт.

## Ручная приёмка

1. Этап 0 (монолит): PW-workflow полностью на примерах-графах; правка файла подхватывается live; теги в UI; ветвление `pw-boot` работает (Timeout-ветка проверяется закрытием клиента на середине входа); Stop бегущего макроса.
2. Демон один: трей, триггеры, автовход, теги — UI не запущен.
3. Панель: открытие/закрытие с полной выгрузкой процесса, живой список, редакторы, Run/Stop.
4. Замер памяти; Exit из трея — оба процесса завершены.

## Риски

| Риск | Митигация |
|---|---|
| Регресс всего PW-workflow (этап 0 переписывает ядро) | Дефолтные примеры 1-в-1 воспроизводят поведение; приёмка этапа 0 до этапа 1 |
| Canvas-редактор — большая UI-работа / сырость NodifyM.Avalonia | Спайк первой задачей W0.4; fallback — самописный Canvas (боксы+рёбра, без мульти-пинов); rows-параметрический режим снимает блокировку |
| Спагетти-графы при росте логики | Осознанный потолок: переменные/выражения в граф не растим; сигнал к ScriptNode/Lua (бэклог) |
| Вечный/зависший граф | Реестр запусков + cancellation + Stop; single-flight по имени; static-warning «цикл без Delay/Wait» |
| Цикл `RunMacroNode` | Глубина ≤ 4 + детект повтора имени в цепочке |
| Хоткей-макрос без селекторов | Валидация при сохранении: «нет контекста — укажи цели» |
| Гонки тегов | `WindowRegistry` — единственный владелец, атомарные операции, селектор = снепшот на момент ноды |
| Чтение отсутствующей переменной | Ошибка ноды → макрос прерывается с логом (не тихий промах); переменная `cursor` пишется всегда, на любой способ запуска |
| Ползучий рост переменных (Set-ноды, выражения) | Жёсткая граница: пишут только триггер и условные ноды; запрос на большее = сигнал к ScriptNode (бэклог), не к расширению графа |
| Пикер хоткеев vs RegisterHotKey в демоне | `SuspendHotkeys`/`ResumeHotkeys` вокруг пикера |
| Кириллица в именах файлов/тегов | Валидация NTFS для файлов; теги — любые строки |
| Обрыв пайпа / гонка инстансов / события раньше снепшота | Reconnect+диалог; mutex; подписка до снепшота + дедуп |
