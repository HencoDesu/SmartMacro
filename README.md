# SmartMacro

**Настольная автоматизация под Windows.** Демон следит за окнами выбранных процессов,
размечает их тегами и гоняет по ним пользовательские макро-графы через сообщения Win32.

<br clear="left">

---

## Что это

По устройству — инструмент общего назначения: какие процессы отслеживать, какие теги
существуют и что делают макросы, задаёт пользователь. По применению — управление примерно
десятью клиентами Perfect World: логин, распознавание классов, действия на всю пачку разом.
Отсюда кириллица в тегах («Лучник», «Жрец») — так их пишет сама игра.

Всё, что программа делает, — это **прогон макроса**. Путь от нажатия до эффекта ровно один:

```
хоткей / появился процесс / кнопка «Запустить»
  → Orchestrator            подбирает окна по селектору тегов
  → MacroExecutor           идёт по графу нода за нодой
  → IMacroPrimitives        ввод, зрение, иконки — по дескриптору окна
```

Макрос — это **граф**, а не список шагов: у ноды поиска два исхода, и ветка «не нашлось»
рисуется автором явно. Хранится он одним файлом `.hsm` — zip без сжатия, внутри паспорт, граф,
свои шаблоны распознавания и свои под-макросы. Файл самодостаточен: отдал его другому человеку
— он работает, потому что картинки едут вместе с графом.

## Как устроено

**Два исполняемых файла, и это несущее решение.**

| | что делает | живёт |
|---|---|---|
| `SmartMacro.Daemon.exe` | движок: трей, хуки, зрение, библиотека макросов, сервер IPC | резидентно, сутками |
| `SmartMacro.exe` | панель: интерфейс, ничего не хранит, всё спрашивает по трубе | по требованию |

Панель не ссылается на `SmartMacro.Core` — поэтому в её выхлопе нет ни OpenCV, ни Tesseract, а
закрытая панель не стоит движку ничего. Общаются по именованной трубе `smartmacro-control`.

Шесть проектов: `Daemon → Core → Contracts → Shared → Native` и `App → Contracts, Shared, Native`.
`Shared` — общий домен (модель графа, валидатор, формат `.hsm`), `Contracts` — протокол.

## Запуск

```bash
dotnet build SmartMacro.slnx                  # всё решение
dotnet run --project src/SmartMacro.Daemon    # движок — поднимать первым
dotnet run --project src/SmartMacro.App       # панель
dotnet run --project tests/SmartMacro.Tests   # ГЕЙТ: 847 тестов
```

Поставка — zip с одной папкой: панель в корне, демон в подпапке рядом со своим окружением.

```bash
dotnet msbuild build/portable.proj -t:Package  # dist/SmartMacro-Release.zip, ~118 МБ
```

**Нужно:** Windows 10+, .NET 10 SDK. Оба исполняемых файла помечены `requireAdministrator` —
без повышения UIPI режет и ввод в окна игры, и захват их экрана.

⚠️ **Если что-то из двух запущено, сборка падает на копировании DLL.** Закрыть окно панели мало:
демон её переживает по замыслу — нужен «Выход» в трее. Ошибки блокировки файла и ошибки
компиляции в выводе выглядят похоже, стоит смотреть внимательно.

## Гейт

Сборка плюс тесты, и **этого не хватает**. Около трёх десятков дефектов в этой базе были невидимы
обоим и найдены только запуском приложения: кольцо фокуса, склипанное в ничто; глифы, приезжавшие
цветными эмодзи и игнорировавшие цвет; текст со срезанными подстрочными элементами; панель,
которая не стартовала вовсе.

Часть измеримого с тех пор забрали обратно `tests/SmartMacro.Tests/Ui/` — обходы раскладки на
настоящей отрисовке Skia: обрезка, перекрытие, выход за край, выживание хвостов у букв, цвет
глифа, невыстреленный `PropertyChanged`. Но правило остаётся: **тронул интерфейс — запусти и
посмотри.**

## Границы, о которых стоит знать сразу

- **Только Windows и только x64.** Инъекция сообщений Win32, `PrintWindow`, повышение прав.
- **Аккорды с модификаторами не работают** через инъекцию сообщений: PW читает модификаторы
  через `GetKeyState`, а межпоточный `SendMessage` его не обновляет. Ноды аккордов нет
  намеренно — работающий на вид код, который в игре молча ничего не делает, хуже отсутствия.
- **Шаблоны пиксельно-точны** для экрана автора 3840×2160.
- **Свежая установка стартует с пустой библиотекой.** Примеров нет: папка, из которой надо
  копировать файлы, объясняет внутреннее устройство вместо того, чтобы дать кнопку.

## Статус

Личный инструмент, не продукт. Английской локализации нет — весь интерфейс, комментарии и
сообщения коммитов по-русски; тексты собраны в один `Strings.resx`, так что перевод стал
возможен, но не сделан.

Что в работе и что решено не чинить — в [задачах](../../issues). Метка `ограничение` стоит на
закрытых: это записанные решения, а не долг.
