# Примеры макросов

Эта папка — **раздаточный материал**, а не рабочие данные.

SmartMacro сюда **ничего не пишет** и отсюда **ничего не читает автоматически**. Библиотека
макросов у демона ровно одна — папка `macros/` рядом с `SmartMacro.Daemon.exe`. Чтобы взять
пример в работу, скопируйте его `.json` в `macros/`: демон подхватит файл на лету
(`FileSystemWatcher`), перезапуск не нужен. Имя файла и есть имя макроса.

Свежая установка открывается с **пустой** библиотекой, и это сделано намеренно.

## Почему так

До этой волны шесть графов `pw-*` были зашиты в код (`DefaultMacroGraphs`), и при первом
запуске их записывал в `macros/` сам конструктор `MacroGraphStore` — вместе с однократной
миграцией унаследованных `macros.json` и `hotkeys.json`. То есть «создать хранилище» означало
«изменить состояние на диске»: тест не мог построить стор, не получив в придачу чужих файлов, а
пользователь не мог понять, откуда в его папке взялись макросы, которых он не писал. Ещё и
удаление примера приходилось делать окончательным через файл-маркер `.examples-seeded`.

Теперь конструктор просто читает папку (инвариант записан в комментарии `MacroGraphStore`), а
примеры живут файлами здесь. Обратная совместимость отменена: мигратора больше нет, и файлы
прежних форматов ни во что не превращаются.

## Что здесь лежит

Шесть графов из бывшего `DefaultMacroGraphs`, **сохранённых как есть** — байт в байт тем, что
писал в `macros/` посев. Это архив-исходник, а не поддерживаемый набор: он воспроизводит то,
что SmartMacro держал зашитым в код до появления графа нод.

| Файл | Триггер | Что делает |
|---|---|---|
| `pw-boot.json` | появление процесса `elementclient_64` | ждёт `ServerSelectButton` → клик → ждёт `CharacterSelectButton` → клик → ждёт `ChatPanelButtons` → `C` → пауза → распознаёт класс → тег + иконка → `C` |
| `pw-immunity.json` | F23 | `F8` во все окна, кроме тега «Шаман» |
| `pw-assist.json` | F19 | клик по слоту 1 отряда → пауза → `F2`; кроме «Лучник» и «Шаман» |
| `pw-cursor-click.json` | F22 | клик по точке из переменной `cursor`, кроме «Шаман» |
| `pw-identify.json` | F20 | веером зовёт `pw-identify-one` по каждому окну |
| `pw-identify-one.json` | нет (библиотечный) | `C` → пауза → распознать класс → тег + иконка → `C` |

⚠️ Оговорки, которые надо знать до того, как копировать:

* **Всё пиксельно точно для экрана 3840×2160.** Координаты кликов и регионы vision на другом
  разрешении не совпадут — правьте в нодах.
* **Теги кириллические** («Лучник», «Шаман»): так их рисует Perfect World. В JSON они записаны
  escape-последовательностями `\uXXXX` — это вывод сериализатора, читается он нормально.
* `pw-boot` и `pw-identify-one` требуют набор шаблонов `classes` в `Assets/templates/classes/`,
  а `SetIconNode` — картинок в `Assets/ClassIcons/`.
* Клавиши F19–F23 выбраны как заведомо свободные: их нет на обычной клавиатуре, их шлёт
  макроклавиша мыши или программируемая панель.

Скоро меняется модель ноды (`Id` станет `Guid`, добавятся `DisplayName` и порог совпадения на
ноду) — после этого файлы выше станут невалидными и будут переписаны. Держим их до тех пор
именно как исходник для переписывания.
